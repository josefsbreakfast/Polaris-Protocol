## 🛰️ Orientation

Cybernetics can become intimidating unnecessarily quickly.

The vocabulary is technical. The diagrams multiply. Feedback,
regulation, control, information, modelling, adaptation and observation
begin interacting with one another before a new reader has had much
opportunity to become comfortable with any of them.

This folder starts more gently.

The aim is not to remove the complexity.

It is to build enough intuition that the complexity becomes easier to
follow.

That means beginning with familiar systems, ordinary language and simple
diagrams before moving into denser theoretical material.

Sometimes the familiar system is Fitzwilliam Darcy.

This is pedagogically defensible.

------------------------------------------------------------------------

## 🪭 Austen Cybernetics

Jane Austen is useful here because *Pride and Prejudice* repeatedly
gives us people:

-   acting from internal models;
-   observing one another;
-   interpreting incomplete information;
-   receiving feedback;
-   discovering prediction errors;
-   revising beliefs;
-   changing behaviour;
-   and affecting one another in return.

In other words, the novel contains excellent small-scale systems.

### 🪭 101 --- Feedback Changes What Happens Next

[`🪭_austen_cybernetics_101.md`](./🪭_austen_cybernetics_101.md)

Start here.

The first node uses Darcy's response to Elizabeth's rejection to
introduce the simplest important idea:

> **Feedback is not merely information received. Its significance lies
> in whether information can return to a system and alter subsequent
> behaviour.**

The arc is:

``` text
behaviour
    ↓
consequences
    ↓
feedback
    ↓
introspection
    ↓
model revision
    ↓
changed behaviour
```

It also introduces the relationship between feedback and agency.

Elizabeth does not merely exist inside Darcy's preferred outcome. She
becomes an independent source of information capable of changing his
model and his behaviour.

🪭 Fan the proto-ally.

### 📚 102 --- The Data Did Not Say That

[`🪭_austen_cybernetics_102.md`](./🪭_austen_cybernetics_102.md)

Once the basic feedback loop is comfortable, make the information
problem harder.

Darcy and Elizabeth both observe real things about one another.

They then assign different meanings to those observations.

This introduces:

-   observation versus inference;
-   signals and decoding;
-   priors;
-   hidden states;
-   observer position;
-   baseline information;
-   asymmetric risk;
-   incomplete information;
-   model divergence;
-   and falsification.

The running teaching case is BooksGate:

``` text
OBSERVATION:
Elizabeth is thinking about Darcy instead of books.

DARCY'S INFERENCE:
😍😍😍

ACTUAL CONTEXT:
Elizabeth is trying to determine whether he is an awful person.
```

The core rule is:

> **The data did not say that. You said that about the data.**

Read 101 before 102.

The first asks:

> **Can information change the system?**

The second asks:

> **How did the system decide what the information meant?**

Those two questions provide a useful foundation for much of what
follows.

## 🧩 Diagram Literacy

The Austen nodes also provide a low-stakes introduction to Mermaid
diagrams.

At first, simply read:

``` text
BOX → ARROW → BOX
```

as:

``` text
this
affects what happens here
which affects what happens next
```

Later diagrams can represent loops, branches, competing models, delays,
boundaries and multiple interacting systems.

There is no need to understand every diagrammatic convention before
beginning.

Follow the arrows.

Ask what information is moving.

Ask what can change.

Ask what cannot.

That is enough to start.

## 🔮 Questions To Carry Forward

As the cybernetics material becomes more complex, keep returning to a
small set of questions:

1.  What is the system doing?
2.  What information can it observe?
3.  What information can return as feedback?
4.  Who or what interprets that information?
5.  Which parts are observation and which are inference?
6.  What assumptions already exist inside the model?
7.  Can contradictory information enter?
8.  Can the system change in response?
9.  Who bears the consequences when the model is wrong?
10. What happens next?

If those questions remain visible, the technical language has something
concrete to attach itself to.
