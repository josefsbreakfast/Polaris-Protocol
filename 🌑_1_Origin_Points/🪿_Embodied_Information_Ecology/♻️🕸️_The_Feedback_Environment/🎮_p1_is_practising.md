# 🎮 P1 Is Practising

**First created:** 2026-08-18 \| **Last updated:** 2026-08-18\
*Interactive systems do not only show players things: they repeatedly
ask players to notice, decide, act, adapt, and practise.*

------------------------------------------------------------------------

## 🛰️ Orientation

A player is not only consuming content.

P1 is doing things.

They are noticing signals, making decisions, testing hypotheses,
learning rules, allocating resources, responding to pressure, failing,
trying again, and gradually becoming better at whatever the system
repeatedly asks them to do.

That gives games a useful property for information-ecology analysis:

> **Interaction creates rehearsal.**

The familiar argument about games often begins somewhere else:

``` text
WHAT DOES THIS GAME DEPICT?

IS THE CONTENT VIOLENT?

IS THE STORY POLITICAL?

IS THIS CHARACTER A GOOD ROLE MODEL?
```

Those questions can matter.

But they are not the same question as:

> **What is P1 practising?**

A game can depict violence while requiring patience, coordination,
communication, spatial reasoning, resource management, or restraint.

A game can tell a story about cooperation while mechanically rewarding
individual accumulation, domination, speed, or status.

A game can contain an explicit moral lesson while repeatedly training
the player to ignore the very information that lesson says should
matter.

The analytical object is therefore not only the representation on the
screen.

It is the loop.

``` text
game state
↓
P1 encounters information
↓
P1 perceives / predicts / decides
↓
P1 acts
↓
system registers action
↓
feedback / consequence / reward / failure
↓
new game state
↓
P1 adapts
↓
repeat
```

P1 is practising.

The question is what.

------------------------------------------------------------------------

## ♻️ Why This Is A Feedback Question

Interactive games are unusually legible examples of feedback
environments because the player's activity can become input into what
happens next.

``` text
environment at T1
↓
player action
↓
registered response
↓
changed environment at T2
↓
new player action
```

The player learns partly because the environment responds.

The response may be:

-   points;
-   damage;
-   survival;
-   death;
-   dialogue;
-   access;
-   exclusion;
-   progression;
-   rank;
-   loot;
-   scarcity;
-   abundance;
-   visual or auditory feedback;
-   another character's behaviour;
-   a changed map;
-   a changed relationship;
-   a changed probability;
-   or simply the discovery that an attempted action does not work.

Repeated interaction can therefore change both sides of the
relationship.

``` text
P1 changes the environment
        ↕
the environment changes P1's next decision
```

That does not mean every game is adaptive in the stronger sense of
modelling the individual player.

A static rule can still create a feedback loop.

The important point is that P1 acts, receives information about the
consequence, and can alter subsequent behaviour.

## 🎯 Mechanics Are Rehearsal

Games teach rules very efficiently.

Often they do not need to explain those rules explicitly.

P1 tries something.

Something happens.

P1 updates.

``` text
ACTION
↓
CONSEQUENCE
↓
INFERENCE
↓
NEXT ACTION
```

Over enough repetitions, deliberate reasoning can become familiarity.

Familiarity can become fluency.

Fluency can become automaticity.

This is one reason the distinction between **what a game depicts** and
**what a player repeatedly does** matters.

``` text
WHAT THE GAME IS ABOUT
≠
WHAT P1 IS PRACTISING
```

Consider a game narratively centred on war.

P1 might actually spend much of the game practising:

-   navigation;
-   rapid visual classification;
-   team communication;
-   resource allocation;
-   timing;
-   prediction;
-   prioritisation;
-   risk assessment;
-   persistence after failure;
-   and coordination under pressure.

Another game may look gentle while repeatedly training:

-   optimisation;
-   accumulation;
-   completion;
-   status comparison;
-   routine;
-   delayed gratification;
-   or compulsive checking.

The surface genre does not tell us the whole cognitive story.

Mechanics matter because mechanics determine what P1 must repeatedly do
in order to continue.

## 🧠 Cognitive Skills Are Not Neutral By Default

Games can be exceptionally good at teaching cognitive operations.

Common examples include:

-   pattern recognition;
-   spatial reasoning;
-   rapid threat classification;
-   map learning;
-   probabilistic inference;
-   strategic planning;
-   resource optimisation;
-   working with incomplete information;
-   persistence through repeated failure;
-   coordination;
-   timing;
-   prediction;
-   and learning complex rule systems without reading a manual.

None of these skills is inherently good or bad.

Nor does practising a skill inside a game mean it will automatically
transfer into another context.

``` text
PRACTICE OCCURRED
≠
TRANSFER OCCURRED
```

But repeated rehearsal is still worth examining.

A useful analysis asks not only whether a game teaches a skill, but:

``` text
WHEN IS THIS SKILL REWARDED?

UNDER WHAT CONDITIONS?

WHAT SIGNALS TRIGGER IT?

WHAT COUNTS AS SUCCESS?

WHAT OTHER POSSIBLE RESPONSES ARE MADE IRRELEVANT?
```

The environment gives the skill a context.

That context is part of what P1 is learning.

## 🕳️ Missing Skills Are Also Design Information

What P1 never has to do can be as informative as what P1 repeatedly
does.

Many games are excellent at making certain problems legible.

``` text
ENEMY
RESOURCE
OBJECTIVE
DAMAGE
DISTANCE
RANK
PROGRESS
INVENTORY
```

Human relationships are less cooperative.

There may be no quest marker showing:

``` text
THIS PERSON IS FRIGHTENED

YOU HAVE MISUNDERSTOOD THEM

THEY SAID YES BECAUSE THEY FELT THEY COULD NOT SAY NO

YOUR FRIEND IS BECOMING CONTROLLING

YOU ARE WINNING THE ARGUMENT AND DAMAGING THE RELATIONSHIP

THE AVAILABLE INFORMATION IS INSUFFICIENT

THE CORRECT ACTION IS TO WAIT
```

Those are harder systems to design.

They involve ambiguity, incomplete information, competing
interpretations, social context, and outcomes that may not become
visible immediately.

That does not mean every game should teach interpersonal repair.

It means that if games are major environments in which people practise
cognition, **the distribution of rehearsal opportunities is worth
noticing**.

Questions include:

-   How often must P1 tolerate uncertainty without resolving it?
-   How often does P1 need to change their mind?
-   Can P1 succeed by de-escalating?
-   Does the game model consent as an ongoing process or a binary gate?
-   Does cooperation require understanding another player, or merely
    using them efficiently?
-   Can P1 repair harm?
-   Can P1 recognise manipulation?
-   Can P1 refuse an offered objective?
-   Is stopping ever represented as successful behaviour?

Absence is not proof of harm.

But absence can still describe the environment.

## 💰 Retention Also Creates Rehearsal

Commercial game design has an obvious reason to care about repeated
interaction.

Players who return, continue, progress, purchase, subscribe, compete,
complete, or remain engaged are economically useful.

That does not make retention mechanics inherently sinister.

A satisfying game also needs reasons to continue playing it.

But a commercially useful mechanic can be cognitively consequential at
the same time.

``` text
GOOD FOR RETENTION
AND
REPEATEDLY REHEARSED
```

are compatible descriptions.

Progression systems, streaks, ranks, collections, daily tasks, variable
rewards, unlocks, scarcity, social comparison, and completion structures
can all shape what P1 repeatedly attends to and does.

The useful question is not:

> **Was this mechanic secretly designed to change P1's personality?**

Usually that would be an absurd evidentiary leap.

The better questions are:

``` text
WHAT BEHAVIOUR DOES THE MECHANIC REQUIRE?

WHAT SIGNAL DOES IT RETURN?

HOW OFTEN DOES THE LOOP REPEAT?

WHAT MAKES P1 CONTINUE?

WHAT MAKES P1 STOP?
```

Intent and effect should not be collapsed.

Neither should commercial purpose and cognitive consequence.

## 🪖 Games, Militaries, And The Bad Causality Problem

Games and simulation have long had relationships with military training,
recruitment, strategic modelling, and cultures of technical mastery.

That relationship is worth studying.

It is also extremely easy to study badly.

``` text
MILITARY USE OF SIMULATION
≠
ALL GAMES ARE MILITARY PROPAGANDA

A GAME NORMALISES A PARTICULAR INTERFACE
≠
THE PLAYER ADOPTS THE POLITICS ASSOCIATED WITH IT

P1 PRACTISES THREAT CLASSIFICATION
≠
P1 BECOMES VIOLENT

REHEARSAL MATTERS
≠
REHEARSAL DETERMINES BELIEF
```

The useful question is narrower.

What kinds of perception, decision-making, hierarchy, cooperation,
competition, threat recognition, technical competence, or response under
pressure become familiar through repeated interaction?

What cultural meanings become attached to those competencies?

What communities form around them?

What happens when the game, the surrounding social environment,
commercial incentives, identity, politics, and other media begin feeding
into one another?

At some point, that may no longer be a question about one game loop.

It may become an ecological question.

Do not blame the controller for the whole ecology.

Do not pretend the controller is irrelevant either.

## 🕸️ The Manosphere Question Is Not "Did Videogames Cause This?"

A serious analysis of gaming and the manosphere should refuse the
easiest causal story.

``` text
BOYS PLAY GAMES
↓
BOYS BECOME MISOGYNISTS
```

is not an adequate model.

Neither is:

``` text
GAMES ARE FICTION
↓
THEREFORE GAME ENVIRONMENTS CANNOT MATTER
```

Interactive systems can contribute to broader environments in which
particular forms of:

-   status;
-   mastery;
-   competition;
-   masculinity;
-   domination;
-   humiliation;
-   technical competence;
-   risk;
-   hierarchy;
-   belonging;
-   and exclusion

become meaningful.

But the game itself is only one possible component.

Players also encounter:

-   peers;
-   streamers;
-   forums;
-   recommendation systems;
-   advertising;
-   political content;
-   pornography;
-   memes;
-   influencers;
-   platform moderation;
-   economic stress;
-   family environments;
-   school;
-   work;
-   and offline relationships.

The question is therefore not whether a game mechanically manufactures
an ideology.

It is whether particular game systems and surrounding information
environments can make some cognitive and social patterns:

``` text
familiar
rewarding
prestigious
repeatable
legible
easy to perform
```

while leaving others comparatively under-rehearsed.

That is a systems question.

It is not a moral panic.

## 🧿 Narrative And Mechanics Can Disagree

Games can say one thing and reward another.

A story may tell P1:

> cooperation matters.

The mechanics may say:

``` text
HELPING COSTS RESOURCES
INDIVIDUAL RANK DETERMINES STATUS
FASTEST PLAYER WINS
OTHER PLAYERS ARE OBSTACLES
```

Or the reverse may happen.

A game can contain an apparently individualistic narrative while its
actual mechanics require constant communication, trust, division of
labour, mutual rescue, and collective problem-solving.

This is why content analysis alone is insufficient.

Ask separately:

``` text
WHAT DOES THE STORY SAY?

WHAT DOES THE INTERFACE MAKE VISIBLE?

WHAT DOES THE MECHANIC REQUIRE?

WHAT DOES THE FEEDBACK REWARD?

WHAT DOES THE COMMUNITY VALUE?
```

Those layers may align.

They may also pull in different directions.

## 🧪 Transfer Is An Empirical Question

P1 becoming excellent at something inside a game does not establish that
the skill, attitude, or behaviour transfers outside it.

Transfer may depend on:

-   similarity between contexts;
-   conscious reflection;
-   repetition;
-   age;
-   prior experience;
-   social reinforcement;
-   emotional salience;
-   whether the player understands the underlying principle;
-   and whether the external environment rewards the same behaviour.

A player can become extraordinarily competent at managing an inventory
without becoming better at packing a suitcase.

A player can also learn a general principle from a highly unrealistic
system.

Both are possible.

Therefore:

``` text
THE GAME CONTAINS A LOOP
≠
THE LOOP CHANGES OFFLINE BEHAVIOUR

THE PLAYER LEARNS THE GAME
≠
THE PLAYER GENERALISES THE LESSON

TRANSFER IS PLAUSIBLE
≠
TRANSFER IS DEMONSTRATED
```

This distinction matters particularly when making claims about violence,
radicalisation, mental health, education, or social behaviour.

The stronger the real-world claim, the stronger the evidence required.

## 🚪 P1 Also Practises Stopping --- Or Does Not

One overlooked part of a game loop is its exit condition.

A system teaches P1 how to continue.

It may also teach P1 when to stop.

Natural stopping cues can include:

-   the end of a level;
-   a save point;
-   a completed day;
-   a finished match;
-   credits;
-   exhaustion of a resource;
-   a narrative pause;
-   a clear checkpoint;
-   or an explicit invitation to leave and return later.

Other systems minimise stopping friction.

``` text
NEXT MATCH

NEXT EPISODE

NEXT TASK

NEXT REWARD

NEXT DAY

NEXT RANK
```

This matters because **continuation is also behaviour**.

If the system repeatedly rewards continuation while making stopping feel
like loss, failure, wasted progress, social abandonment, or missed
opportunity, then the exit architecture deserves analysis alongside the
reward architecture.

This does not mean long play is inherently harmful.

It means:

> **What does P1 practise when deciding whether to remain inside the
> loop?**

is a legitimate design question.

Where sustained informational input begins altering bodily awareness,
time perception, attention, or reflective self-experience, the analysis
crosses towards **🫥 Experiential Saturation** in
`🫀🕸️ Information Is Experienced`.

## 🛠️ The P1 Practice Audit

When analysing an interactive system, ask:

``` text
WHAT DOES P1 HAVE TO NOTICE?

WHAT CAN P1 IGNORE?

WHAT COUNTS AS SUCCESS?

WHAT GETS REWARDED?

WHAT GETS PUNISHED?

WHAT MUST BE REPEATED?

WHAT BECOMES EASIER WITH PRACTICE?

WHAT BECOMES AUTOMATIC?

WHAT DOES THE INTERFACE MAKE LEGIBLE?

WHAT DOES IT HIDE?

WHAT DOES P1 LEARN TO DO UNDER PRESSURE?

WHAT DOES P1 LEARN TO DO WHEN NOTHING IS HAPPENING?

WHAT SOCIAL BEHAVIOUR IS MODELLED?

WHAT SOCIAL BEHAVIOUR IS ABSENT?

CAN P1 CHANGE THEIR MIND?

CAN P1 REPAIR A MISTAKE?

CAN P1 REFUSE THE OBJECTIVE?

CAN P1 SUCCEED BY WAITING?

WHAT DOES THE SYSTEM DO AFTER P1 ACTS?

WHAT INFORMATION RETURNS TO P1?

HOW DOES P1 ADAPT?

WHAT IS THE EXIT CONDITION?

WHAT HAPPENS IF P1 REFUSES THE LOOP?

WHAT PART OF THIS PRACTICE COULD TRANSFER ELSEWHERE?

WHAT EVIDENCE EXISTS THAT IT ACTUALLY DOES?
```

The audit is not a morality score.

A game does not fail because it does not teach every desirable human
skill.

The purpose is to make the rehearsal structure visible.

## 🕹️ From Diagnosis To Design

Once we ask what P1 is practising, another question follows:

> **What could we deliberately let P1 practise?**

Games can provide relatively low-stakes environments in which players
encounter:

-   unfamiliar systems;
-   uncomfortable decisions;
-   incomplete information;
-   difficult social situations;
-   failure;
-   consequences;
-   and opportunities to retry.

That possibility belongs primarily in:

[🕹️ Building Safer Sandboxes](./🕹️_building_safer_sandboxes.md)

The distinction is:

``` text
WHAT IS THIS SYSTEM TRAINING THROUGH REPEATED INTERACTION?
→ 🎮 P1 IS PRACTISING

WHAT COULD WE INTENTIONALLY DESIGN A SYSTEM TO HELP PEOPLE REHEARSE?
→ 🕹️ BUILDING SAFER SANDBOXES
```

The first is diagnostic.

The second is constructive.

## 🚦 What This Node Does Not Claim

This node does not claim that:

-   games determine personality;
-   violent games straightforwardly cause violence;
-   gaming causes misogyny;
-   all repetition transfers into offline behaviour;
-   all retention design is manipulation;
-   military interest in games makes games military technology;
-   realism determines psychological effect;
-   fictional representation is irrelevant;
-   or players are passive objects of game design.

P1 is an active participant.

Players interpret, resist, joke, mod, cooperate, sabotage, refuse
objectives, invent new games inside games, and use systems in ways
designers did not anticipate.

That is part of the feedback environment too.

The point is simpler:

> **If a system repeatedly asks a person to perform an operation, gives
> them feedback, and lets them adapt, then it is reasonable to ask what
> they are getting practice at doing.**

That question should come before the causal grand theory.
