# 🕹️ Building Safer Sandboxes

**First created:** 2026-08-18 \| **Last updated:** 2026-08-18\
*Games can create low-stakes spaces for practising difficult systems,
unfamiliar situations, and better responses without pretending the
simulation is reality.*

------------------------------------------------------------------------

## 🛰️ Orientation

A sandbox is useful partly because it is **not** the thing it models.

Nobody needs a game to reproduce reality perfectly before they can learn
something from interacting with it.

Games can simplify.

They can exaggerate.

They can make hidden variables visible.

They can compress time.

They can let P1 fail without producing the full consequences that
failure would carry elsewhere.

They can permit another attempt.

``` text
attempt
↓
feedback
↓
consequence
↓
reflection / adaptation
↓
retry
```

That makes interactive systems potentially valuable environments for
practising situations that are difficult, unfamiliar, emotionally
loaded, dangerous, expensive, rare, or simply hard to explain in prose.

The important word is **practising**.

A safer sandbox does not need to tell P1 what to believe.

It can let P1 encounter a system, make decisions inside it, receive
feedback, discover consequences, and try something different.

This node therefore asks:

> **What could we deliberately design interactive environments to help
> people rehearse?**

Its companion node, [🎮 P1 Is Practising](./🎮_p1_is_practising.md),
asks what existing systems already train through repeated interaction.

This node turns the question around.

If interaction creates rehearsal, what might be worth rehearsing on
purpose?

------------------------------------------------------------------------

## 🧪 The Sandbox Is Valuable Because It Is Not Reality

Simulation is often discussed as though greater realism necessarily
produces greater educational value.

It does not.

A model always preserves some things and discards others.

A useful sandbox makes choices about which relationships matter for the
thing being explored.

``` text
REALITY
↓
SELECTED RELATIONSHIPS
↓
MODEL
↓
INTERACTION
```

The question is not:

> **Is this exactly what reality is like?**

It is:

> **Does this model preserve enough of the relevant relationship for P1
> to learn something useful by interacting with it?**

A flight simulator needs different fidelity from a game about grief.

A procedural training environment needs different fidelity from a game
designed to help someone recognise coercive behaviour.

A fictional town can teach systems literacy while allowing a human being
to put an implausible number of sharks in their pockets.

Abstraction is not automatically a defect.

Sometimes abstraction is what makes a difficult system safe enough to
inspect.

## 🧠 Practising Difficult Things Before They Are Real

Some situations are difficult to teach because knowing the rule is not
the same as recognising the situation when it arrives.

A person can be told:

``` text
COERCION MAY BE SUBTLE
```

without becoming good at recognising coercion.

They can be told:

``` text
TRAUMATISED PEOPLE MAY BE INCONSISTENT
```

without understanding what it feels like to make decisions around
incomplete, contradictory, or delayed information.

They can be told:

``` text
MISINFORMATION EXPLOITS SOCIAL SIGNALS
```

without ever having to decide what to trust while the relevant
information is uncertain.

Interactive environments can potentially let people rehearse:

-   recognising coercive control;
-   bystander decisions;
-   responding to grief;
-   supporting someone in distress;
-   conflict de-escalation;
-   repair after harm;
-   uncertainty and incomplete information;
-   misinformation and source evaluation;
-   group pressure;
-   disability and access needs;
-   care work;
-   poverty and administrative burden;
-   institutional decision-making;
-   unfamiliar cultural or social environments;
-   moral injury;
-   competing obligations;
-   and decisions where there is no clean optimal answer.

The goal does not have to be:

``` text
FIND THE CORRECT BUTTON
```

It can be:

``` text
NOTICE MORE
↓
TRY SOMETHING
↓
SEE WHAT THAT CHANGES
↓
REASSESS
```

That is a different kind of learning.

## 🎭 Mechanics Can Carry Meaning

There is an important distinction between:

``` text
A GAME TELLS A STORY ABOUT A DIFFICULT EXPERIENCE
```

and:

``` text
THE MECHANICS MAKE P1 WORK WITH
SOME OF THE STRUCTURAL CONDITIONS
OF THAT EXPERIENCE
```

A game about poverty might tell P1 that money is scarce.

A mechanic can make every available choice consume a resource required
somewhere else.

A game about disability might explain fatigue in dialogue.

A mechanic can force P1 to plan around a limited and variable energy
budget.

A game about bureaucracy might tell P1 that a process is confusing.

A mechanic can distribute necessary information across contradictory
forms, inaccessible interfaces, deadlines, and offices that do not share
records.

A game about trauma might tell P1 that memory and behaviour can become
inconsistent under stress.

A mechanic can make certainty itself unavailable.

Mechanics can therefore communicate relationships that exposition
struggles to reproduce.

This does not automatically make the representation accurate.

It makes the representation **procedural**.

That is something we can examine.

## 🔁 Retry Changes The Learning Environment

One of the unusual affordances of games is the possibility of repetition
without identical real-world cost.

``` text
choice A
↓
outcome
↓
retry
↓
choice B
↓
different outcome
```

That can make difficult material more explorable.

P1 may be able to:

-   test an assumption;
-   discover that it was wrong;
-   restart;
-   try a less familiar response;
-   compare consequences;
-   recognise a pattern;
-   or become comfortable with uncertainty through repetition.

Failure can become information rather than catastrophe.

That matters particularly where fear of getting something wrong prevents
people from practising at all.

A sandbox can say:

> **You are allowed to misunderstand this once. Look at what happened.
> Try again.**

That is not trivial.

Many real systems provide extremely poor environments for learning
because mistakes are punished before the person understands the rule.

## 🧿 Perspective Is Not The Same As Possession

Games are often praised for allowing players to "experience what it is
like" to be another person.

That claim needs restraint.

A simulation cannot give P1 ownership of somebody else's life.

Playing a game about:

-   racism;
-   disability;
-   migration;
-   poverty;
-   grief;
-   trauma;
-   war;
-   abuse;
-   or discrimination

does not mean P1 now knows what that lived experience is.

``` text
SIMULATED PERSPECTIVE
≠
LIVED EXPERIENCE

EMPATHETIC ENGAGEMENT
≠
EXPERTISE

PLAYING THE MODEL
≠
POSSESSING THE REALITY
```

A safer claim is that interactive systems can expose P1 to
**relationships, constraints, trade-offs, or informational conditions
they may not otherwise have considered**.

That can be valuable without pretending simulation collapses
experiential distance.

Sometimes the ethical design choice is precisely to preserve that
distance.

## 🧯 Therapeutic-Adjacent Is Not Therapy

Games already exist that engage with:

-   depression;
-   anxiety;
-   grief;
-   trauma;
-   recovery;
-   loneliness;
-   identity;
-   relationships;
-   and other psychologically difficult experiences.

Some players may find them useful.

Some developers may deliberately draw on psychological research,
clinical expertise, or lived experience.

But several categories must remain distinct.

``` text
ENTERTAINMENT

PSYCHOEDUCATION

REFLECTIVE / THERAPEUTIC-ADJACENT DESIGN

CLINICALLY INFORMED INTERVENTION

VALIDATED THERAPEUTIC INTERVENTION
```

These are not interchangeable labels.

A moving game about depression is not automatically treatment for
depression.

A game that helps one person process trauma is not therefore a validated
trauma intervention.

A developer consulting a clinician does not establish efficacy.

A therapeutic claim requires evidence appropriate to the claim.

This is an area where enthusiasm can outrun governance very quickly.

## ⚖️ Quality Control Matters

If games are deliberately used for psychoeducation, social learning,
therapeutic-adjacent work, or other sensitive forms of rehearsal,
quality control becomes important.

Useful questions include:

``` text
WHAT DOES THE GAME CLAIM TO DO?

IS THAT AN EDUCATIONAL CLAIM OR A CLINICAL CLAIM?

WHAT EVIDENCE SUPPORTS IT?

WHO HELPED DESIGN THE MODEL?

WERE PEOPLE WITH RELEVANT LIVED EXPERIENCE INVOLVED?

WERE RELEVANT PROFESSIONALS INVOLVED?

WHAT DOES THE MODEL SIMPLIFY?

WHAT DOES IT OMIT?

COULD THE MECHANIC REINFORCE THE OPPOSITE LESSON?

ARE CONTENT AND INTENSITY SIGNALLED CLEARLY?

IS THE GAME ACCESSIBLE TO THE PEOPLE IT CLAIMS TO HELP?

WHAT HAPPENS IF P1 BECOMES DISTRESSED?

DOES THE GAME TELL P1 WHERE THE MODEL ENDS?
```

The answer does not always need to be regulation.

It may involve:

-   independent review;
-   evidence labels;
-   age guidance;
-   accessibility information;
-   clear descriptions of intended purpose;
-   lived-experience review;
-   professional review where appropriate;
-   content signalling;
-   and explicit limits on therapeutic claims.

The key is not to turn every meaningful game into a medical device.

It is to stop pretending that **entertainment**, **education**, and
**treatment** are the same evidentiary category.

## 🧵 A Simulation Can Show Its Seams

A persistent design anxiety is that revealing a limitation will damage
immersion.

Sometimes the opposite is true.

Players can tolerate extraordinary abstraction when they understand the
rule.

Games already ask players to accept:

-   compressed time;
-   impossible inventories;
-   repeated lives;
-   simplified economies;
-   tiny worlds;
-   selective memory;
-   characters who repeat dialogue;
-   objects appearing from nowhere;
-   and physics that have politely agreed not to attend.

The problem is not necessarily that the model contains a seam.

The problem is often that P1 cannot tell **where the seam is or what
happens when they cross it**.

``` text
SEAM
+
LEGIBLE EXPECTATION
=
USABLE MODEL
```

A simulation does not have to pretend to be seamless in order to remain
meaningful.

## 🐇 Cole Was A Guest Today

Consider a small example from *Animal Crossing: New Horizons*.

A hotel system can allow visiting villagers to return and recognise that
they have stayed before.

The ordinary resident lifecycle can operate under different continuity
rules.

A former resident encountered again may effectively appear as a fresh
instance rather than preserving the relationship P1 previously had with
them.

Those two systems create an awkward design question if hotel guests are
allowed to become permanent residents.

``` text
HOTEL GUEST
↓
persistent visitor continuity

RESIDENT
↓
different residency / re-encounter continuity
```

Now cross the seam:

``` text
HOTEL GUEST
↓
BECOMES RESIDENT
↓
MOVES AWAY
↓
RETURNS TO HOTEL
↓
?????????
```

What should the character remember?

The hotel stay?

The residency?

Both?

Neither?

Does hotel continuity survive becoming a resident?

Does the older residency system now need to preserve information it was
not designed to preserve?

From P1's perspective, the desired affordance is beautifully simple:

> **HI NINTENDO. COLE WAS A GUEST TODAY. I WOULD LIKE THE BUNNY.**

From the system's perspective, the bunny may have just crossed two
different models of identity.

The important design lesson is not that Nintendo---or any
developer---must engineer perfect continuity before allowing the
feature.

It is:

> **A useful affordance does not necessarily need to be withheld because
> the simulation cannot preserve every state perfectly.**

If the unavoidable compromise is understandable, tell P1.

For example:

``` text
IF HOTEL GUESTS BECOME RESIDENTS,
SOME PREVIOUS VISIT MEMORIES MAY NOT
BE PRESERVED AFTER LATER MOVE-OUTS.
```

Then players can decide whether the trade-off matters to them.

And where the choice is genuinely about preference rather than technical
necessity, developers can ask.

``` text
WOULD YOU RATHER:

A) RECRUIT HOTEL GUESTS,
   WITH SOME MEMORY DISCONTINUITY

OR

B) KEEP HOTEL AND RESIDENT
   CONTINUITY SYSTEMS SEPARATE?
```

Players are capable of understanding this.

They already understand that the game is a constructed system.

## 🦈 Thirty Great White Sharks Fit In Your Pocket

This is worth stating explicitly.

*Animal Crossing* allows P1 to carry an impressive quantity of marine
megafauna without requiring a forklift, aquarium, oxygen supply,
structural reinforcement, or explanation.

Respect.

The game remains emotionally meaningful.

Nobody concludes that friendship with a villager is meaningless because
the inventory system has taken an adventurous position on shark volume.

That gives us a useful distinction:

``` text
REALISM
≠
COHERENCE

SEAMLESSNESS
≠
TRUST

ABSTRACTION
≠
FAILURE

LEGIBLE LIMITS
CAN PRESERVE TRUST
```

A model earns trust partly by behaving consistently enough for P1 to
orient themselves inside it.

Perfect simulation is not required.

Sometimes telling P1:

> **this bit is game logic**

is considerably better than contorting the entire system to conceal the
join.

## 📣 Signal The Compromise Before P1 Finds It

Expectations are part of system design.

If developers know that a feature contains an important limitation,
signalling that limitation can change how it is experienced.

``` text
UNEXPECTED DISCONTINUITY
→ BUG? BETRAYAL? CONFUSION?

EXPECTED DISCONTINUITY
→ KNOWN MODEL LIMIT
```

The underlying technical limitation may be identical.

The informational environment is not.

Advance signalling can:

-   reduce confusion;
-   distinguish limitations from bugs;
-   let players make informed choices;
-   reduce false expectations;
-   make trade-offs legible;
-   preserve trust;
-   and teach players something about how constructed systems work.

This principle extends beyond games.

A system does not become more trustworthy by hiding every approximation.

Sometimes trust comes from knowing which approximation you are looking
at.

## 🗳️ Sometimes You Can Just Ask P1

Not every design decision should be crowdsourced.

Players may not know the engineering constraints.

Different player groups may want incompatible things.

Popularity does not automatically produce good design.

But some decisions genuinely involve a preference trade-off.

If developers can implement:

``` text
FEATURE
+
KNOWN IMPERFECTION
```

and do not know whether players would prefer that to:

``` text
NO FEATURE
+
PERFECTLY PRESERVED EXISTING RULE
```

there is useful information available from the people who will encounter
the trade-off.

Ask them.

A poll does not surrender design authority.

It can establish:

-   which discontinuities players actually care about;
-   what level of imperfection they will tolerate;
-   which expectations need signalling;
-   and whether an internally elegant rule is protecting something the
    audience does not particularly value.

Consultation can also prepare the community for the compromise before
release.

That changes the informational conditions under which the feature
arrives.

## 🧒 Children Can Understand That Games Have Rules

There is sometimes an unnecessary assumption that acknowledging seams
will confuse younger players.

Children who can play a moderately complex game are already learning
distinctions between:

``` text
WHAT HAPPENS IN THE GAME

WHAT HAPPENS IN REALITY

WHAT THIS GAME ALLOWS

WHAT THIS GAME DOES NOT ALLOW

WHAT PERSISTS AFTER SAVING

WHAT RESETS

WHAT DIFFERENT OBJECTS CAN DO
```

Games are systems-literacy environments whether designers call them that
or not.

A child does not need a lecture about object instances, database state,
or persistence architecture.

They can understand:

> **If this character moves in, the game might not remember every
> earlier visit later.**

That is enough.

In fact, exposing manageable seams can teach a useful general principle:

> **Models have boundaries.**

Once P1 understands that, imperfection does not automatically destroy
meaning.

## 🛠️ A Safer Sandbox Design Tool

When designing or assessing an interactive environment intended to help
P1 practise something difficult, ask:

``` text
WHAT IS P1 SUPPOSED TO PRACTISE?

WHAT RELATIONSHIP MUST THE MODEL PRESERVE?

WHAT CAN SAFELY BE ABSTRACTED?

WHAT DOES P1 NEED TO NOTICE?

WHAT INFORMATION IS DELIBERATELY WITHHELD?

WHAT COUNTS AS FAILURE?

WHAT DOES FAILURE COST?

CAN P1 RETRY?

WHAT DOES THE RETRY TEACH?

IS THERE ONE CORRECT ANSWER,
OR IS P1 LEARNING TO NAVIGATE UNCERTAINTY?

DO THE MECHANICS TEACH THE SAME LESSON AS THE STORY?

WHOSE EXPERIENCE IS BEING MODELLED?

WHO HELPED BUILD THAT MODEL?

WHAT DOES THE MODEL NOT ENTITLE P1 TO CLAIM THEY NOW UNDERSTAND?

IS THIS ENTERTAINMENT, EDUCATION,
THERAPEUTIC-ADJACENT, OR TREATMENT?

WHAT EVIDENCE SUPPORTS THAT LABEL?

WHAT ARE THE SEAMS?

DOES P1 KNOW WHERE THEY ARE?

WHAT STATE OR CONTINUITY CANNOT BE PRESERVED?

CAN THAT LIMITATION BE SIGNALED?

WOULD P1 PREFER THE IMPERFECT FEATURE
TO NO FEATURE AT ALL?

CAN WE ASK THEM?

WHAT IS THE EXIT CONDITION?

HOW DOES P1 RETURN FROM THE SANDBOX
TO THE WORLD OUTSIDE IT?
```

The purpose is not to make games solemn.

It is to make deliberate use of what games are already extremely good at
doing:

**letting people practise inside systems.**

## 🚦 What This Node Does Not Claim

This node does not claim that:

-   games are substitutes for therapy;
-   simulation produces lived experience;
-   every game should be educational;
-   every game needs a moral lesson;
-   realism is undesirable;
-   players should design games by referendum;
-   children need technical explanations of game architecture;
-   imperfect systems are automatically acceptable;
-   signalling excuses harmful design;
-   or every difficult social problem can be gamified safely.

Some things should not be turned into games.

Some models will be misleading.

Some mechanics will trivialise what they attempt to represent.

Some therapeutic claims will exceed the evidence.

Some seams will break the thing the simulation is supposed to preserve.

The point is narrower:

> **Interactive systems can create unusually powerful rehearsal spaces,
> and those spaces can be designed with greater care about what P1 is
> practising, what the model preserves, what it cannot preserve, and how
> clearly those limits are communicated.**
