🇮🇷 Strategic warning: Gulf submarine cables

On 23 October, Reuters reported that two senior Iranian security officials described plans to attack submarine communications cables if US–Israeli military strikes resume.

The reported threat includes potentially obstructing repairs to prolong disruption.

The distinction is important:

Threatened capability and intent ≠ attempted attack ≠ confirmed infrastructure damage.

Potential consequences include disruption to Gulf telecommunications, financial transactions, cloud connectivity and regional data-centre operations.

The global impact should not be exaggerated: Reuters reports that less than 1% of international bandwidth passes through the Strait of Hormuz, although particular Gulf countries and services may have much greater exposure.

This is a significant escalation in publicly reported infrastructure coercion, not a confirmed cyber incident.

C. 🟣 Systemic vulnerabilities and active exploitation

1. 🚨 VeloCloud Orchestrator — confirmed active exploitation

CVE-2026-114625
Vendor disclosure: 22 October
CISA KEV addition: 23 October
Severity: CVSS 9.9 (v3.1); 9.4 (v4.0)

Arista Networks confirms active exploitation of a SQL-injection vulnerability affecting on-premises VeloCloud Orchestrator.

An attacker with an authenticated session, including the lowest built-in tenant role, can potentially obtain highly privileged operator access.

Affected versions include:

* 5.2.x before 5.2.3.18
* 6.1.x before 6.1.3.10
* 6.4.x before 6.4.2.12

Hosted versions have reportedly already been patched.

The significance is the affected product’s position in network administration. Compromising an orchestrator may expose management functions and information about distributed networks.

However, compromise of an orchestrator does not automatically establish compromise of every downstream network device.

The vendor has not publicly identified an attacker, an Iranian connection or the number of affected customers.

Confidence: 🟢 Vulnerability, affected versions and active exploitation; ⚪ actor attribution and downstream operational consequences.  

Arista Security Advisory 0199⁠￼

2. 🚨 Collabora Online / Nextcloud — exploitation now recognised by CISA

CVE-2026-110447
Observed attacks: September–October 2026
Public vulnerability disclosure: 14 October
CISA KEV addition: 23 October
Severity: CVSS 9.2

This affects the optional Collabora Online Built-in CODE Server application used with Nextcloud.

The vulnerable component is richdocumentscode before 26.4.303.

Under particular conditions, an unauthenticated attacker can execute operating-system commands.

The vendor states that the vulnerable path becomes available when the built-in CODE server is not running, including during certain restarts or failures.

Standalone Collabora Online installations are not affected by this specific flaw.

This matters for government, education, healthcare and other organisations using self-hosted collaboration infrastructure.

The chronology is especially important:

Exploitation was reported before the formal CVE disclosure.

The 23 October KEV addition is a new authoritative acknowledgement of exploitation, not a new attack onset.

The vendor recommends upgrading or removing the affected application; merely disabling it is insufficient.  

Collabora's original security advisory⁠￼

The Canadian Cyber Centre reports that proof-of-concept material exists for the earlier PHP vulnerabilities but says it has not identified confirmed active exploitation of those vulnerabilities at the time of its 23 October update.

Confidence: 🟢 Vulnerability and mitigation; ⚪ successful exploitation of the newly disclosed issue.

What is becoming clearer?

The important pattern is not a demonstrated common attacker.

It is the increasing security significance of shared administrative infrastructure.

Network orchestrators, document-collaboration platforms, programming-language runtimes and cloud providers can each support numerous downstream organisations.

That creates several different risks:

* A compromised management system may provide access beyond the original host.
* A vulnerable shared software component may expose otherwise unrelated organisations.
* A non-malicious infrastructure failure may interrupt multiple essential services.
* Emergency remediation may itself create service-continuity problems.

These are related dependency mechanisms, but they are not evidence of one coordinated campaign.

The Iranian submarine-cable threats introduce a separate concern: deliberate targeting of physical infrastructure supporting digital services.
